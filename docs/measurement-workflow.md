# 量測回填與狀態管理

[範例 04](../examples/04_measurement_workflow.py) 示範如何記錄分批回傳的實驗結果，使用固定配方清單與單一目標 `Campaign`。輔助類別只存在於範例中，不是新增的套件 API。

**候選 ID 識別配方，量測 ID（trial ID）識別一次實驗。** 重複量測或重試仍使用相同候選 ID，但必須建立新的量測 ID，即使前一次失敗或取消也一樣。已回填的結果或已取消的實驗不能重複處理。

| 事件 | 紀錄方式 | 是否用於訓練 |
| --- | --- | --- |
| 派出實驗 | 將量測 ID 與實驗條件加入 `PendingBatch`。 | 否 |
| 回填 `success` | 將有限的實測值寫入 `ObservationBatch`，移除該筆待測狀態。 | 是 |
| 回填 `warning` 或 `failed` | 保留狀態與取得的量測值，移除該筆待測狀態。 | 否 |
| 取消實驗 | 移除待測狀態；範例的取消紀錄保留量測 ID 與原因。 | 不建立觀測值 |

`record_returns` 依量測 ID 對齊派出的實驗條件，不依資料列順序。如果任何 ID 未知、重複，或已不在待測清單中，整批回填會被拒絕。成功結果必須有有限實數；警告或失敗結果可以沒有量測值（`None`，儲存為 JSON `null`），不會用預測值填補。部分回填只移除已回填的實驗，其他實驗仍維持待測，包括條件相同的另一次量測。

推薦器仍會排除已觀測條件，包括警告與失敗紀錄。範例透過明確派出實驗來安排刻意重測，不要求推薦器重新選出相同配方。

手動派出也會檢查 `Space` 的硬性參數限制；重試不代表可以跳過限制。這項檢查不等於對新量測結果或實驗操作安全提供保證。

**儲存與恢復。** 範例將配方清單、量測與配方 ID 對照、取消紀錄和 `Campaign.to_state()` 一起儲存在 JSON。載入時透過 `Campaign.from_state()` 還原，繼續等待尚未回填的量測。外層 JSON 格式屬於範例，不能直接交給 `Campaign.load_checkpoint()`。透過範例輔助類別回填與派出實驗，避免自行呼叫 `tell_batch` 或 `set_pending` 後造成兩份紀錄不同步。

載入時會比對待測、已回填與取消的 ID，確認各狀態互不衝突，且實驗條件與配方對照一致；不一致就拒絕載入。序位參數中混用小數與大整數時，也會保留原始值，不依賴 pandas 自動推斷成浮點數。

在內層 `expdoe-dk` 套件目錄執行：

```sh
conda run -n expdoe-dk-codex env PYTHONPATH=src python ../examples/04_measurement_workflow.py
```

示範使用模擬量測與暫存檔：恢復時仍有一筆待測實驗，接著取消它，並以新的量測 ID 重試失敗配方。印出的歷史只包含兩筆成功量測。

這是單一程序的教學範例，不是完整實驗室資訊系統；不提供多人同時寫入、原子檔案替換或已結案紀錄更正。請保留受控的儲存檔，不任意編輯其內容。
